# Parameterized NTT/INTT Accelerator Core

A fully parameterized, constant-geometry (Pease) Number Theoretic Transform accelerator
for lattice-based post-quantum cryptography — supporting **ML-KEM (Kyber)**,
**ML-DSA (Dilithium)**, and **FN-DSA (Falcon-512 / Falcon-1024)** from a single RTL
codebase.

**Key features:**
- Constant-geometry (Pease) algorithm — zero bank conflicts, zero crossbar logic
- Dual butterfly units — 100% utilization, 2 lanes/cycle, N/4 cycles per stage
- Unified CT/GS butterfly — shared multiplier saves ~40% datapath area vs. split pipelines
- FSR one-hot ring counter for stage tracking — no binary counter or decoder
- Compile-time parameterization — one `SCHEME` enum in `ntt_pkg.sv` selects all parameters
- Full-precision Barrett reduction — verified against FIPS 203 ML-KEM reference
- FIPS 203 cross-validated test suite — 16 self-checking cases with Python golden model
- All 7 RTL modules independently verified — unit tests + integration + round-trip


## 3. Scheme Parameterization

Switch the target scheme by changing one line in `rtl/ntt_pkg.sv`:

```systemverilog
parameter scheme_e SCHEME = KYBER;   // or DILITHIUM, FALCON_512, FALCON_1024
```

All derived parameters are computed automatically:

| Scheme | N | Q | W | MULW | LOGN | ZETA |
|---|---|---|---|---|---|---|
| KYBER | 128 | 3329 | 13 | 26 | 7 | 17 |
| DILITHIUM | 256 | 8,380,417 | 24 | 48 | 8 | 1753 |
| FALCON_512 | 512 | 12,289 | 14 | 28 | 9 | 7 |
| FALCON_1024 | 1024 | 12,289 | 14 | 28 | 10 | 7 |

**Important:** `Q-1` must be divisible by `2N` for a complete radix-2 NTT.
- Kyber: `Q-1 = 3328 = 2^8 * 13` → max `N = 128` (this matches FIPS 203)
- Dilithium: `Q-1 = 8,380,416 = 2^13 * 1023` → max `N = 256`
- Falcon: `Q-1 = 12,288 = 2^12 * 3` → max `N = 1024`

After changing SCHEME, regenerate the twiddle ROMs and test vectors:
```bash
(cd scripts && python3 gen_vectors.py)
```

## 4. Architecture

### 4.1 Pease Constant-Geometry NTT

The design uses the Pease formulation rather than standard Cooley-Tukey.

| Property | Cooley-Tukey | Pease (constant-geometry) |
|---|---|---|
| Pairing per stage | `(i, i + stride)`, stride=2^k | `(i, i + N/2)` always |
| Inter-stage permutation | Bit-reversal (requires buffer reorder) | 1-bit circular address rotation |
| Bank conflicts with dual BU | Yes (variable stride) | No (guaranteed conflict-free) |
| Crossbar logic needed | Yes (grows O(N^2)) | Zero (pure wire permute) |

### 4.2 Unified Butterfly Datapath (`butterfly_unit.sv`)

```
CT mode (FWD):    t = w * b;       a' = a + t;   b' = a - t
GS mode (INV):    t = w * (a - b); a' = a + b;   b' = t
```

One shared multiplier serves both modes. Mode is controlled by a single `ct_mode` signal
selecting operand routing. One pipeline register (configurable, `PIPELINE=1`) between the
multiply stage and add/sub stage.

### 4.3 Dual Butterfly + Ping-Pong Buffers

- Two butterfly units running in parallel, each handling one lane
- Two N-word ping-pong buffers: read from one, write to the other
- Stage completes in N/4 cycles (100% BU utilization during RUN)
- Round-trip FWD+INV (Kyber): ~580 cycles (226 FWD + 354 INV including 1/N scaling)

### 4.4 FSR Stage Sequencer (`reorder_unit.sv`)

- LOGN-bit one-hot ring counter tracks the current stage
- `ru_rotate`: combinational 1-bit circular left-rotate for the perfect shuffle
- `tw_exp_gen`: combinational twiddle-ROM address derivation

The FSR replaces a binary counter + comparator + decoder chain, toggling only
1 bit per stage transition (minimal dynamic power).

### 4.5 Twiddle ROM (`twiddle_rom.sv`)

- Depth N/2 covers all LOGN stages (proven exhaustive)
- Dual-port: both BUs fetch independently each cycle
- Two planes at the same address: `omega^e` (FWD) and `omega^{-e}` (INV)

### 4.6 Control FSM (`ntt_top.sv`)

```
IDLE → RUN (LOGN stages × N/4 cycles) → SCALE (INV only, N cycles) → DONE
```

FWD starts at buffer A, ends at buffer B (bit-reversed spectrum).
INV starts directly at buffer B (chaining off a preceding FWD), ends at buffer A
(natural order), after the 1/N scaling pass.

## 5. Performance

| Metric | KYBER | DILITHIUM | FALCON-512 | FALCON-1024 |
|---|---|---|---|---|
| FWD cycles | 226 | 514 | 1,154 | 2,562 |
| INV cycles (incl. 1/N) | 354 | 770 | 1,666 | 3,586 |
| Round-trip cycles | ~580 | ~1,284 | ~2,820 | ~6,148 |
| BU utilization | 100% | 100% | 100% | 100% |
| Logic area (est. NAND2 gates) | ~1,650 | ~4,200 | ~1,900 | ~1,900 |
| Storage (FF/SRAM bits) | ~5,000 | ~18,400 | ~43,000 | ~86,000 |

At 100 MHz, a Kyber round-trip completes in 5.8 us. At 500 MHz: 1.16 us.

## 6. Verification

### 6.1 Unit Tests (6 testbenches)

Each sub-module has a dedicated self-checking testbench:

| Testbench | Module | Vectors | Tests |
|---|---|---|---|
| `tb_barrett` | `barrett_reduce` | 200 | Random operands, edge cases (0, Q-1, overflow) |
| `tb_butterfly_comb` | `butterfly_unit` (unpiped) | 200 | 100 CT + 100 GS, random (a,b,w) |
| `tb_butterfly` | `butterfly_unit` (pipelined) | 200 | Same vectors, checks pipeline latency |
| `tb_tw_exp` | `tw_exp_gen` | 448 | All stages × all lanes (7×64 for Kyber) |
| `tb_rotate` | `ru_rotate` | 256 | All addresses × FWD/INV mode |
| `tb_ntt_top` | `ntt_top` | 1 poly | FWD NTT + round-trip FWD→INV (128 coefs) |

### 6.2 Multi-Case Test Suite (16 cases)

`tb_ntt_suite.sv` with `IDX=0..15` parameter runs against NIST-verified vectors.

| IDX | Description | Input |
|---|---|---|
| 0 | All zeros | 128 × 0 |
| 1 | All ones | 128 × 1 |
| 2 | All Q-1 | 128 × 3328 |
| 3 | Unit impulse (coeff 0 = 1) | [1, 0, 0, ..., 0] |
| 4 | Mid impulse (coeff 64 = 1) | [0,...,0,1,0,...,0] |
| 5 | Last impulse (coeff 127 = 1) | [0,...,0,1] |
| 6 | Alternating ±1 | [1, -1, 1, -1, ...] |
| 7 | Alternating +1/0 | [1, 0, 1, 0, ...] |
| 8..11 | Random seed=0..3 | Pseudorandom |
| 12 | Half-range max | 64 × (Q-1), 64 × 0 |
| 13 | All Q-1 but one zero | |
| 14 | Near-overflow mix | Values near Q boundary |
| 15 | FIPS 203 known-answer | Reference vector from standard |

### 6.3 Golden Model

`scripts/testsuite.py` generates all test vectors and validates them against both:
- The Pease NTT golden model (`scripts/gen_vectors.py`)
- The Kyber CT reference NTT from FIPS 203 (ML-KEM)

All cross-checks must match before vectors are written to the `testsuite/` directory.

## 12. Bugs Caught During Verification

Two real bugs documented in the RTL comments (left intentionally as instructive examples):

1. **Scale-stage pipeline desync** — Write address registered one cycle to match
   Barrett's latency, but the Barrett result was combinational. Fixed by registering
   result alongside its address.

2. **Reorder rotate direction** — INTT read-side permutation initially used
   rotate-right (natural but wrong). Exhaustive comparison against golden model
   across all 7 stages located the exact divergence point.

## 13. Future Work

- **Side-channel countermeasures**: Uniform dataflow provides timing resistance
  naturally; DPA masking/shuffling can be added at the BU level.
- **Pipelined Barrett**: Split the internal multiplier for higher clock frequencies.
- **SoC integration**: Memory bus (AXI/AHB) wrapper, DMA support, interrupt controller.
- **GPGPU integration**: Vortex SIMT pipeline warp-level NTT instruction (research gap).
- **Multiplier-bank expansion**: 4+ BUs for higher throughput with guaranteed
  conflict-free access (property of the constant-geometry formulation).
- **HLS port**: The uniform loop structure is naturally amenable to High-Level Synthesis.
